`aphrody-labs/kitesurf` (fork of cloudflare/kitesurf, submodule of `browser` at `third_party/kitesurf`) is a Rust/WASM browser engine (Blitz, Stylo, Taffy, Vello, Parley, Boa), not Chromium; Chromium 160 stays the reference engine, kitesurf the edge engine (needs Workers Paid for Dynamic Workers).

- Patches: applied as one commit each on the `kitesurf` branch of forks parley, blitz, anyrender, taffy, stylo, boa, resvg, vello, ratatui-image, jpeg-encoder, cut from the exact commit in each crate's `.cargo_vcs_info.json` (`browser/tools/kitesurf-absorb.ts`). Cargo.toml hunks target the normalized published manifest and are replayed on the upstream form.
- `kitesurf/crates/` holds 26 crates named `browser-<crate>` (library names unchanged), generated by `browser/tools/kitesurf-monorepo.ts` from the reverse-dependency closure of the patched crates; `FEATURES.md` is the feature matrix. Proof on fr1: wasm `cargo check`, 771 host tests, `cargo publish --dry-run` of all 26. blitz-html must ask blitz-dom for `svg` and `floats` (kitesurf's patches do not build with them off).
- Publishing: workflow `publish-crates` in the kitesurf repo uses the org secret CARGO_REGISTRY_TOKEN (never read); new crates are rate limited to 1 per 10 minutes after a burst of 5, the workflow retries.
- Bun: `bun.lock` replaced `pnpm-lock.yaml` for developers; Bazel still reads the pnpm lockfile, the patch series and two node:test files (e2e-global-setup, lint rule tests) that fail under `bun test`.
- Error 1027 cause: the GitHub App `aphrody-labs` delivers every event type to the `aphrody-github` Worker, which keeps only workflow_run, push, release, security alerts, installation. Event subscriptions are editable only in the App settings page, behind GitHub's sudo password prompt (an agent cannot pass it).

**Why:** owner asked to fork kitesurf, absorb and merge its patches into one prefixed publishable workspace on Bun, and to choose every decision himself.
**How to apply:** change engine code in `kitesurf/crates`, not in `scripts/patches`; see [[toolchain-policy-and-ay-tools]] and [[autonomy-nhitl]].
