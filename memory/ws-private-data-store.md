No data about the owner's PC, the VPS fleet or the state of the work in tracked docs or agent files. Everything generated by agents, the learning loop or telemetry (reports, inventories, probe results, plans, research notes, boot logs, audits) goes to a private git-ignored store; only code, schemas, specs, standards, tests with fixtures and generic procedures are tracked.

**Why:** 2026-11-17 the owner ordered it after generated plans, inventories and host audits had been committed to public repositories.

**How to apply:** in aphrody-dev/ay use `tools/local.ts` (`privatePath(rel, root, forWrite)` gives `.private/<rel>`, `AY_PRIVATE_DIR` overrides; `readAy()` merges the git-ignored `ay.local.toml` over `ay.toml` for host aliases, host paths and checkout hints). Name hosts by role in docs (`<build-host>`, `<test-host>`, `<prod-host>`). `bun tools/private-gate.ts` (part of `bun run check`) fails when a tracked file repeats a local value, a user profile or home path, an e-mail or a public IP. Other repos get the equivalent ignored directory. Scheduled loops run on the fleet, not in public CI (a public workflow's output is public). History already pushed is not rewritten without the owner's decision. Link: [[dig-deep-for-goals]], [[naming-and-privacy]].
