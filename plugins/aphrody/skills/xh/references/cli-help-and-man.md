# xh CLI Help & Man Page Reference (`v0.26.3`)

Grounded in `src/cli.rs`, `src/generation.rs`, `doc/xh.1.md`, `FAQ.md`, and `xh help` (`xh 0.26.3 +native-tls +rustls`).

## Synopsis & Binary Invocation Modes

```text
xh [OPTIONS] <[METHOD] URL> [REQUEST_ITEM]...
```

- **`[METHOD]`**: Optional HTTP method (must be ASCII alphabetic). Defaults to `GET`, or `POST` if body items, `--raw`, or stdin are present.
- **`URL`**: Scheme defaults to `http://`, or `https://` when `--https` is passed or `argv[0]` stem is `xhs`, `https`, or `xhttps`.
  - `:8000` -> `http://localhost:8000/`
  - `:/path` -> `http://localhost/path`
  - `://example.org` -> `http://example.org/`
- **HTTPie compatibility mode**: Activated when binary stem is `http` or `https`, or when `XH_HTTPIE_COMPAT_MODE` is set. Disables default `--check-status`.
- **Order-sensitive negation**: Every `--OPTION` has a hidden `--no-OPTION` counterpart generated by `Cli::into_app()`. Options apply left-to-right so the last flag wins (e.g. `--offline --no-offline`).

## Exit Codes (`src/main.rs`, `src/error_reporting.rs`)

- `0`: Success (or HTTP `416` when `--continue` detects an already-complete download).
- `1`: CLI usage, syntax, I/O, or network error.
- `2`: Request timeout (`reqwest::Error::is_timeout()`).
- `3`: HTTP `3xx` with `--check-status` and without `--follow`.
- `4`: HTTP `4xx` with `--check-status`.
- `5`: HTTP `5xx` with `--check-status`.
- `6`: `TooManyRedirects` (`--max-redirects` exceeded).

## Environment Variables & Config Files

- `XH_CONFIG_DIR`: Overrides `~/.config/xh` (Linux/macOS) or `%APPDATA%\xh` (Windows).
- `XH_HTTPIE_COMPAT_MODE`: Disables default `--check-status`.
- `REQUESTS_CA_BUNDLE` / `CURL_CA_BUNDLE`: Custom PEM CA bundle fallback when `--verify` is omitted.
- `ALL_PROXY`, `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`: Proxy configuration (ignored if `--proxy` is passed).
- `NETRC`: Custom `.netrc` location.
- `NO_COLOR`: Disables colors (sets `--pretty` default to `format` on TTY).
- `RUST_LOG`: `env_logger` filter used with `--debug`.
- `config.json`: `{ "default_options": ["--native-tls", "--style=solarized"] }` prepended before argv.

## Header Encoding Note (`FAQ.md`)

Per RFC 7230, HTTP header values are officially US-ASCII with opaque `obs-text`. Since v0.23.0, `xh` renders non-ASCII header bytes using ISO-8859-1 (matching browser `fetch()` / DevTools) and appends `(UTF-8: ...)` if the bytes also decode cleanly as UTF-8.
